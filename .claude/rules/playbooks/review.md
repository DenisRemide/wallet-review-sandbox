# Playbook: spec-review

Инструкция для команды `/spec-review [ref]`. Ревью всех изменений в ветке (или diff относительно `ref`, по умолчанию `master`).

## Вход

- `[ref]` — базовая ветка / коммит для diff'а. По умолчанию `master`.

## Алгоритм

1. **Получи список изменённых файлов** через `git diff --name-only <ref>...HEAD`.
2. **Отфильтруй**: только `.ts` файлы в `src/`. Тесты, конфиги, docs — отдельно, в конец отчёта.
3. **Для каждого изменённого файла:**
   - определи тип через `manifest.yaml` → `file_types`;
   - прочитай **только diff** через `git diff <ref>...HEAD -- <file>`, не весь файл;
   - для контекста прочитай файл целиком только если diff не самодостаточен;
   - применить playbook `check.md` к изменениям (не ко всему файлу — только к тому, что поменялось).
4. **Собери агрегированный отчёт:**
   - группировка по severity (errors → warnings → info);
   - внутри каждой группы — по файлам;
   - в конце — summary: сколько файлов затронуто, сколько нарушений по severity.
5. **Оцени delta скоринга** относительно последнего отчёта в `.claude/reports/`:
   - прочитай `.claude/reports/` → найди файл с наибольшей датой;
   - сравни нарушения по спекам;
   - если изменения **улучшают** какой-то показатель — отметь;
   - если **ухудшают** — подсвети красным флагом, особенно если падение > `scoring.degradation_threshold` в manifest.

## Формат отчёта

```
# spec-review vs master

**Изменённых файлов (src/*.ts):** 12
**Base:** master (abc1234)
**Head:** docs/spec (def5678)

## Ошибки (2)

### src/modules/intent/use-case/create-intent/create-intent.handler.ts
- R03:error — run() возвращает Promise<void>, должен Promise<Result<..>>
  @ line 23: `return;`

### src/modules/intent/infrastructure/repositories/intent/intent.repository.ts
- R02:error — throw new Error вместо err('...')
  @ line 41: `throw new Error('intent not found');`

## Предупреждения (3)
...

## Info (5)
...

## Delta скоринга (vs 2026-04-13-baseline)

| Спека | Было | Стало | Δ |
|---|---|---|---|
| R02 | 9.0 | 8.5 | -0.5 ⚠ |
| R03 | 9.0 | 8.0 | -1.0 ⚠ |
| R11 | 3.0 | 3.0 | 0 |

**Overall:** 72 → 70 (-2)

## Вердикт

- ❌ merge блокируется: есть R02:error и R03:error
- fix required: исправить 2 ошибки, после — перезапустить /spec-review
```

## Правила поведения

- **Не выходи за пределы diff.** Не комментируй код, который не менялся, даже если в нём есть нарушения (для этого есть `/spec-audit`).
- **Не комментируй тесты как нарушения R-правил.** Для тестов — отдельная секция в конце.
- **Не исправляй код.** Только отчёт.
- **Delta скоринга опциональна** — если в `.claude/reports/` нет baseline, пропусти эту секцию с явным указанием.
- **Если diff пустой** — сообщи об этом и выйди.

## Сохранение отчёта

- После ревью спроси у пользователя: сохранить отчёт в `.claude/reports/<YYYY-MM-DD>-review-<branch>.md`?
- Сохранять только по явному согласию — эти отчёты будут коммититься в репозиторий.
